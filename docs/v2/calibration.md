# 기준 데이터 보정 기록 (PLAN_v2 §8)

- **시드**: 보정 전용 시드 1~9만 사용했다. 탐색 시드(100~119)와 확인 시드(1000~1029)는 쓰지 않았다.
- **분모**: 부하 기준(D8)이다.
  - DOWN 비율 = DOWN / (PROCESSING + DOWN)
  - 준비 비율 = SETUP / (SETUP + PROCESSING)
  - Rev.A는 공급 제약 때문에 유휴 시간이 길다. 관측시간을 분모로 쓰면 그 설계 결함이 현상 파라미터 보정에 섞이므로 부하 기준을 택했다.
- **보정 대상**: 품질, 고장, 준비 같은 현상 파라미터만이다. 설비 대수, 인원, 버퍼, K, (s, Q), 숙련은 보정하지 않았다. `calibration.py`는 현상 키가 아닌 override를 거부한다(테스트로 확인).
- **절차(D9, 사전 등록)**: 품질 → 고장 → 준비 순서로 본다.
  - 범위를 벗어난 현상만 클래스 공통 배율 1개로 조정하고, 9시드 평균을 범위 중앙에 맞춘다.
  - 격자 탐색은 최대 5회로 제한한다.

- **채택 근거**
  - **품질**: 반복 0에서 95.2%(95% CI 94.96~95.45%)로 범위 안이라 바꾸지 않았다.
  - **고장**: 반복 0에서 7.33%(95% CI 6.71~7.95%)로 범위 안이라 바꾸지 않았다.
    - 스테이션별로는(반복 2 기준) R1 12.7%, S3 12.2%가 cnc_winder 클래스 특성상 상한 근처다. 다만 기준은 설비 평균이라 조정하지 않았다.
  - **준비**: R1과 S3가 모두 범위를 크게 넘었다.
    - 정적 계산으로 보면 초기값에서 단위당 준비(0.62 × 300 = 186s)가 가공(193s)과 비슷했다.
    - 공통 배율 격자 {0.10, 0.125, 0.15} 가운데 두 공정 평균이 중앙 10%에 가장 가까운 0.125를 택했다. (R1 10.76% + S3 9.25%) / 2 = 10.0%다.
  - 반복은 4회로, 상한 5회 이내다.
- **동결 결과**
  - `configs/v2/rev_A.yaml`: R1 `setup_group_change_s` 300 → 37.5, S3 240 → 30.
  - `data/v2/assumptions.csv`: 해당 행을 evidence_type=derived로 바꾸고 근거를 적었다.
  - 그 밖의 현상 파라미터는 초기값 그대로다.
- **해석상 주의**
  - 준비시간이 1/8로 줄어든 것은 실측으로 확인한 사실이 아니다. 합성 범위(5~15%)에 맞춘 결과일 뿐이다.
  - 초기 합성값이 범위와 맞지 않았다는 뜻이며, 실제 CNC 전환 시간에 대해 말해 주는 것은 없다.

## 워밍업 (MSER-5, D24)

- **데이터**: 보정 시드 1~9, 실행 길이 240h의 시간당 양품 출하 수열을 썼다.
- **결과**: 5개 묶음 MSER의 절단점 d*가 9시드 모두 0h였다(반복 0~3 모두). 기록 파일은 각 실험 디렉토리의 `mser.csv`, `warmup_decision.json`이다.
- **결정**: 시드별 d*의 최댓값 0h ≤ 계획 80h이므로, 규칙에 따라 **워밍업 80h(1주)를 유지**했다.
- **해석**
  - Rev.A는 공급 제약으로 출하율이 초기부터 거의 일정해서 MSER가 초기 편향을 검출하지 못했다.
  - 다만 초기 하우징 재고 900개가 소진되는 구간이 있으므로, 80h 유지는 보수적인 선택이다.
  - 이 결정은 결과를 본 뒤 바꾸지 않았다.
