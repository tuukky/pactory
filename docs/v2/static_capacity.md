# 정적 부하 계산 (Rev.A, 시뮬레이션 전 손계산)

PLAN_v2 §5. 아래 값은 **가설**이며 결과가 아니다. 대기, 막힘, 동시 고장, 투입 통제 같은 동적 상호작용은 들어 있지 않다. [시뮬레이션 진단](final_report.md)과 비교할 기준선으로만 쓴다.

**생성 명령**
```
python -m factory_sim.static_capacity --config configs/v2/rev_A.yaml
```
설정은 보정 동결 후 Rev.A다(준비시간 R1 37.5s, S3 30s, calibration.md). 수요는 18대/h이고, FIFO일 때 군 전환 확률은 1 − Σp² = 0.620이다.

**각 열의 계산 방법**
- **+준비**: 단위당 준비 = 0.62 × 준비시간. R1은 23.25s, S3는 18.6s다.
- **+고장**: 가공 × (1 + MTTR/MTBF). 고장 시계가 가공 중에만 흐르기 때문에 이 형태가 된다.
- **오븐 실효 능력**
  - 만재 24개가 아니라, 입력 버퍼 제약을 반영한 실효 배치로 계산한다.
  - 가공 중에는 입력 6 + 상류 S4가 막힌 채 들고 있는 2개, 합계 8개만 쌓이고, 하역 직후 한꺼번에 챔버에 들어간다.
  - 그 뒤 형성 대기 900s 동안 수요율로 4.5개가 더 들어와 배치는 12.5개가 된다.
  - 주기는 1800 + 900 = 2700s이므로 16.7대/h이고, 고장을 반영하면 15.4대/h다.
  - 900s를 형성 시작 시점부터 재는 이유는 model_spec의 C1 결정을 따른다.

## 자원·공급 계산

| 항목 | 계산 | 값 |
|---|---|---|
| 작업자 | 주문당 작업자 필요시간 558s × 18/h | 상시 2.79명 / 8명 (이용률 0.35) |
| AGV | 구간 운반 × (이동 + 상하차), 충전 가용률 0.889 | 1개씩 적재 시 4.20대, 4개 묶음 시 1.05대 / 보유 3대 |
| 하우징 (s, Q) | 리드타임 중 수요 576 > s = 300이므로 미착 주문이 늘 1건. 주기 = 32h + (Q − s)/D | **공급 상한 12.3대/h** |
| 키트 K | K / (투입→FA 체류 하한 40분) | CONWIP 상한 45.1대/h |

## 예상 병목 순위 (가설)

1. **하우징 공급**: 12.3대/h < 수요 18. 공정이 아니라 자재 정책이 1차 제약이 될 것으로 예상한다.
2. **S5 오븐**: 실효 15.4대/h < 18이며, 이용률 1.17로 공정 중 유일하게 1을 넘는다.
3. **R1 CNC**: 이용률 0.41. 다만 R1 숙련자가 OP1 한 명뿐이라(skills.yaml) 준비 대기 손실이 정적 계산보다 커질 수 있다. 정적 계산에는 이 숙련 제약이 들어 있지 않다.
4. **S3 권선기**: 이용률 0.38.

그 밖의 공정은 이용률이 0.32 이하다. AGV는 묶음 적재가 2개 수준이면 약 2.1대가 필요해 3대로 여유가 있을 것으로 본다.

## 시뮬레이션과의 차이

- Rev.A 처리량은 13.3대/h였다. 정적 하우징 상한 12.3보다 높은 이유는 초기 재고 900개가 관측창 앞부분을 받쳐 주기 때문이다.
- 투입은 관측시간 100% 동안 막혔다. 그중 64%는 K 슬롯이 가득 차서, 36%는 하우징 결품 때문이었다. 정적 계산의 K 상한(45대/h)으로는 이 현상이 보이지 않는다.
  - 원인: 키트 체류 시간이 오븐 배치 대기 때문에 하한 40분보다 훨씬 길다. 처리량 13.3대/h, K = 30이면 Little 법칙으로 약 2.3시간이다.
- 정적 계산은 오븐(이용률 1.17)을 공정 병목으로 꼽았다. 시뮬레이션에서는 투입이 막혀 오븐 가공 비율이 42%에 그쳤다. 처리량을 정한 것은 공정 능력이 아니라 공급과 투입 통제였다.
