# v3 기준선 보고서: 기하 기반 6D 자세 추정과 로봇 가이던스

작성일: 2026-10-30 / 대상: PLAN_v3 1~3주차(§2.1 우선순위 1~5) / 세부 근거: `docs/v3/verification.md`, `docs/v3/model_spec.md`

> **이 보고서의 LM-O 수치는 모두 개발(dev) 세트 50장 결과다.** 평가(eval) 세트 50장은 아직 한 번도 쓰지 않았고,
> 기준선과 개선판(PLAN_v4)을 모두 동결한 뒤 같은 eval 세트에서 한 번에 평가한다. 따라서 여기 수치는 최종 성능이 아니라
> **개선 방향을 정하기 위한 진단 결과**다.
> 하우징 CAD, 간이 장면, 체커보드, 가상 로봇 자세 결과는 **합성**이며 실제 설비 성능 검증이 아니다.

## 1. 요약

- 학습 없이 Depth의 형태 정보만 쓰는 파이프라인(평면 제거 → DBSCAN 분할 → FPFH+RANSAC → ICP)을 만들었다.
- 공개 데이터셋 LM-O(가림이 심한 다물체 장면)에서 **ADD(-S) 성공률은 32.5%** 다(dev, 366대상).
- 정답 영역을 직접 주면 **58.5%** 까지 오른다. 손실의 대부분은 정합이 아니라 **분할과 대상 식별** 단계에서 생긴다.
- 로봇 관점에서 더 심각한 문제는 **오채택**이다. 파이프라인이 "성공"이라고 내놓은 결과 중 **63%가 오답**이다.
  신뢰도 검사가 다른 물체에 잘못 맞춘 결과를 거의 거르지 못한다.
- 캘리브레이션과 가이던스 계산은 검증을 통과했다. 오차 예산 분석 결과, 현재 가정에서는 Hand-eye 병진 오차가
  TCP 위치 허용치(±2 mm)를 지키지 못하게 하는 가장 큰 요인이다.

## 2. 무엇을 만들었나

```text
Depth (+ 내부 파라미터)
  → Point Cloud 역투영 → 전처리(깊이 ROI, voxel, 이상점 제거, 법선)
  → 평면 RANSAC 제거 → DBSCAN 클러스터 + 크기 필터 → 후보 최대 20개
  → 후보마다 FPFH + RANSAC(재시작 5회) → point-to-plane ICP
  → 신뢰도 검사(fitness, RMSE, 가시 표면 비율) → 대칭 후보
  → T_base_tcp = T_base_cam · T_cam_obj · T_obj_grasp → 접근각·작업영역 검사
```

| 모듈 | 내용 |
|---|---|
| `geometry.py` | 핀홀 카메라, 투영·역투영(픽셀 중심 규약 고정), SE(3) |
| `segment.py`, `pose.py` | 위 파이프라인 1~8단계, 단계별 처리시간 기록 |
| `metrics.py` | ADD, ADD-S, 대칭 고려 회전 오차, 대칭축 오차 |
| `datasets.py` | BOP 로더, dev/eval 분리와 eval 접근 차단 |
| `calib.py` | 체커보드 내부 파라미터, eye-to-hand Hand-eye 5개 방법 |
| `guidance.py` | TCP 목표 계산, 파지 선택, 몬테카를로 오차 예산 |

모든 임계값은 `configs/v3/pipeline.yaml`에 있고, 조정 9건은 dev 결과로만 정했으며 근거를 남겼다(verification §5).

## 3. 평가 방법

- **데이터**: BOP LM-O `test_bop19`, scene 2, 물체 8종. 200장 중 dev 50장, eval 50장.
  eval은 dev 프레임과 im_id가 5 이상 떨어진 프레임에서만 뽑아, 연속 촬영의 인접 프레임이 섞이지 않게 했다.
- **성공 기준**: 평균 거리 오차 < 물체 지름 × 0.1 (BOP 관례). 대칭 물체(eggbox, glue)는 ADD-S, 나머지는 ADD.
- **두 가지 설정**
  - **dbscan (주 결과, 사전 고정)**: 아무 정보 없이 Depth만으로 대상을 찾는다.
  - **gt_mask (정합 상한)**: 정답 가시 마스크로 대상 영역을 직접 준다. 분할이 완벽할 때 정합이 얼마나 되는지를 본다.
- 색 정보(RGB)는 두 설정 모두 쓰지 않았다.

## 4. 결과

### 4.1 전체

| 지표 | dbscan (주 결과) | gt_mask (상한) |
|---|---|---|
| **ADD(-S) 성공률** | **32.5%** | **58.5%** |
| 채택률 (파이프라인이 "성공"으로 낸 비율) | 87.2% | 71.9% |
| 오채택률 (채택했지만 오답) | 54.6% | 13.4% |
| **채택 결과의 정밀도** (채택 중 정답 비율) | **37.3%** | **81.4%** |
| 신뢰도 검사를 무시했을 때 성공률 | 32.5% | 66.1% |
| 처리시간 중앙값 / 대상 | 10.6 s | 0.87 s |

### 4.2 손실은 어디서 생기나

```text
대상 366개 (100%)
 ├─ 대상 영역이 후보 20개 안에 없음 ············ 33.1%  → 이 중 정답 2.5%   (분할 손실)
 └─ 대상 영역이 후보 안에 있음 ················· 66.9%  → 이 중 정답 47.3%  (식별 + 정합 손실)
                                                  ─────
                                         전체 성공 32.5%

정답 영역을 직접 주면 (gt_mask) ·························· 58.5%  (정합 상한)
  └ 신뢰도 검사가 정답까지 거부한 몫 ······················ +7.6%p → 66.1%
```

- **분할 손실 (가장 큼)**: 물체들이 서로 붙어 있거나 가려서 DBSCAN이 대상을 다른 물체와 합치거나 잘게 나눈다.
- **식별 손실**: 대상 영역이 후보에 있어도, 형태만으로는 "어느 덩어리가 이 물체인지" 구별하지 못하고 다른 덩어리에 더 잘 맞춘다.
- **신뢰도 검사의 한계**: 오답을 걸러야 할 검사가 오답은 거의 통과시키고(실패 코드 LOW_FITNESS 0.3%, LOW_VISIBILITY 12.6%),
  가림이 큰 정답은 거부한다.

### 4.3 물체별 (ADD(-S) 성공률)

| obj | 물체 | 대상 수 | dbscan | gt_mask |
|---:|---|---:|---:|---:|
| 1 | ape | 45 | 37.8% | 53.3% |
| 5 | can | 50 | 42.0% | 58.0% |
| 6 | cat | 45 | 4.4% | 11.1% |
| 8 | driller | 50 | 42.0% | 66.0% |
| 9 | duck | 40 | 40.0% | 75.0% |
| 10 | eggbox (대칭) | 46 | 17.4% | 63.0% |
| 11 | glue (대칭) | 40 | 52.5% | 82.5% |
| 12 | holepuncher | 50 | 26.0% | 62.0% |

- cat은 정답 영역을 줘도 11.1%다. 분할이 아니라 **정합 자체가 약한 물체**라서, 다음 단계에서 따로 원인을 봐야 한다.
- eggbox는 dbscan과 gt_mask 차이가 45.6%p로 가장 크다. 납작한 형태라 테이블이나 다른 물체와 쉽게 섞인다.

### 4.4 가시 비율별 (정답 가시 비율 visib_fract)

| 가시 비율 | 대상 수 | dbscan | gt_mask |
|---|---:|---:|---:|
| ≤ 0.3 | 16 | 6.3% | 6.3% |
| 0.3 ~ 0.6 | 59 | 3.4% | 13.6% |
| 0.6 ~ 0.8 | 75 | 29.3% | 46.7% |
| > 0.8 | 216 | 43.5% | 78.7% |

물체가 거의 다 보이면(> 0.8) 정합 상한은 78.7%다. 그런데 dbscan은 43.5%에 그친다. 잘 보이는 물체에서도 분할과 식별 손실이 크다는 뜻이다.

### 4.5 처리시간

전체 10.6 s 중 RANSAC이 약 9.3 s다. 후보 약 20개 × 재시작 5회를 모두 돌리기 때문이다.
대상과 무관한 후보를 미리 걸러내면 정확도와 속도가 같이 좋아질 여지가 크다.
(측정 중 다른 작업이 동시에 돌아 처리시간이 부풀었을 수 있다. 최종 평가에서 단독 실행으로 다시 잰다.)

### 4.6 캘리브레이션과 가이던스 (합성)

| 항목 | 결과 |
|---|---|
| 내부 파라미터 | 재투영 RMS 0.06~0.07 px, 초점거리 오차 중앙값 ≤ 0.34 px |
| Hand-eye, 노이즈 0 | PARK, HORAUD, ANDREFF, DANIILIDIS 수치 오차 수준으로 복원. TSAI는 250회 중 1회 퇴화 |
| Hand-eye, 기준 노이즈 (0.05°/0.25 mm, 15자세) | 중앙값 0.85 mm / 0.064° |
| 종단 경로 (렌더링 → 코너 검출 → solvePnP → Hand-eye) | 0.25~0.50 mm / 0.015~0.019° |
| 가이던스 손계산 대조 | 일치 |
| 간이 합성 bin 장면 (같은 하우징 5개 × 3장면) | 15개 중 13개 채택, 오채택 0, 채택 중 파지 성공 84.6% |

**오차 예산 (TCP 허용치 ±2 mm, 성공률 기준 95%)**: 자세 오차만이면 98.6%, Hand-eye 오차만이면 88.5%, 둘을 합치면 72.6%다.
평균제곱 기준 기여도는 Hand-eye 64%, 자세 35%다. 현재 가정에서는 허용치를 지키지 못하며, **Hand-eye 병진 오차를 줄이는 것이 먼저**다.

## 5. 해석

1. **정합 알고리즘보다 앞단이 병목이다.** 같은 정합 모듈이 정답 영역에서는 58.5%, 스스로 찾은 영역에서는 32.5%다.
2. **로봇에게 위험한 것은 오채택이다.** 인식 실패는 재촬영으로 회복할 수 있지만, 잘못된 자세로 파지를 시도하면 충돌이나 낙하로 이어진다.
   채택 정밀도 37.3%는 실제 셀에 쓸 수 없는 수준이다. 성공률과 함께 **오채택률을 핵심 지표로 관리**해야 한다.
3. **목표 시나리오(같은 하우징 bin-picking)에서는 식별 문제가 사라진다.** 빈 안의 덩어리는 모두 하우징이므로 "어느 물체인가"를 묻지 않는다.
   간이 합성 장면에서 오채택이 0이었던 이유다. 다만 하우징끼리 붙는 분할 문제와 뒤집힘(180°) 오인식은 남는다.
4. **LM-O에서 색은 가장 싼 개선 수단이다.** 데이터에 RGB가 있고 물체 모델에도 정점 색이 있는데 지금은 쓰지 않는다.

## 6. 한계

- LM-O 수치는 dev 50장 결과이며, 임계값 일부를 dev로 정했으므로 낙관적일 수 있다. 최종 수치는 eval 1회 평가로 낸다.
- LM-O 라이선스를 아직 확인하지 않았다. 결과를 공개 배포하기 전에 확인한다.
- Kinect depth 편향(정답보다 수 mm 멂)을 보정하지 않았다.
- ADD-S는 하우징 뒤집힘(180°)을 정답으로 판정할 수 있다. 파지 성공 판정에서는 TCP 오차로 잡는다.
- Open3D RANSAC은 멀티스레드라 같은 시드에서도 결과가 미세하게 달라진다.
- 캘리브레이션과 가이던스는 합성 데이터와 가상 로봇 자세로만 검증했다.
