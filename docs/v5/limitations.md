# v5 한계

결과를 읽을 때 같이 봐야 하는 조건이다. PLAN_v5 §12에 미리 적은 항목과, 실행 중에 드러난 항목을 나눠 적는다.

## 계획 단계에서 정한 한계 (PLAN_v5 §12)

- **전부 합성이다.** 하우징 bin 영상(BlenderProc), 깊이 노이즈·결측 모델, 그리퍼, 하우징 질량(0.30 kg), VP 촬영 시간(0.3 s), 수동 처리 시간(60 s), VP 고장은 모두 합성 가정이다. 실제 로봇·카메라·공장 성능을 주장하지 않는다.
- **S2는 자세 오차를 옮겨 심은 방식이다.** MuJoCo 카메라 영상으로 비전을 다시 돌린 폐루프가 아니다. 하우징은 정답 회전으로 혼자 놓이고, 이웃 하우징·빈 벽과의 간섭은 없다.
- **표본이 작다.** S1 eval은 조건별 20장면이고, VP 분포는 그중 기준·적재 20 조건에서 만들었다. 드문 실패는 CI가 넓다.
- v2 공장 모델의 한계(AGV 혼잡 무시, 정비 인력 미모델, 납기 포화)를 그대로 물려받는다.
- 개발에 AI 코딩 도구를 썼다. 문제 정의, 가설, 판정 기준, 결과 해석은 직접 했다.

## 실행 중 드러난 한계

| 항목 | 내용 | 영향 |
|---|---|---|
| 옆으로 누운 하우징 | 빈 안 하우징의 상당수가 30° 넘게 기울어 있다. 파지 정의가 위·아래 두 곳뿐이라 이런 하우징은 집을 후보가 아니다 (`APPROACH_LIMIT`) | 채택률이 낮게 나오는 주원인. 비전 실패가 아니라 파지 정의의 한계 |
| 물리 충돌 형상 | BlenderProc 낙하 시뮬레이션은 하우징 볼록껍질로 충돌을 계산했다 | 실제보다 덜 촘촘하게 쌓인다 |
| 깊이 노이즈 σ ≥ 2 mm | B1의 v4.1 깊이 일관성 검사 문턱값이 σ 1 mm 기준이다. σ 4 mm에서 B1 오채택 16/16 | 노이즈가 큰 센서에서는 문턱값을 다시 정해야 한다(새 dev가 필요, 이번에는 조정하지 않음) |
| S2 장면 수 | G-GT·G-NOISE를 '기준 20장 + 적재 20 20장'이 아니라 **B1이 채택한 장면**(기준 13, 적재 20 9)에서만 돌렸다. 집을 대상 하우징은 비전이 고른 후보로 정해지므로, 채택이 없는 장면은 대상이 없다 | 구현 단계에서 정했으나 PLAN에 기록하지 않았고, eval 뒤에 확인했다. G1·G4 판정의 n이 계획보다 작다 |
| 파지 실패 유형 | 오채택 자세의 실패는 모두 '집지 못함'이었고 낙하는 없었다. 이웃 하우징이 없고 하우징이 정지해 있어서일 수 있다 | 실제 bin에서는 빗나간 손가락이 이웃 하우징을 밀어낼 수 있다 |
| p_fail = 0 | S2 G-EST가 22/22 성공이라 VP의 '채택 후 파지 실패' 확률이 0으로 들어갔다 | 0이 아니라 '22회 중 0'이다 (Wilson 95% 상한 약 15 %). 민감도 실험이 이 범위를 덮는다 |
| 실행 환경 | Windows 앱 제어 정책이 `blenderproc.exe`와 torchvision 네이티브 모듈을 차단했다. 렌더는 같은 env의 python으로, B1 학습·예측은 WSL2(같은 GPU·같은 패키지 버전)로 옮겼다 | 결과에는 영향 없음. 재현 절차가 두 환경으로 나뉜다 |
